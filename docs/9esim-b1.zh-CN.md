# ZTE U60 Pro 中的 9eSIM B1

U60 Pro 没有内置 eSIM，只有一个 nano-SIM 卡槽。**9eSIM B1** 是一张标准 SIM 形态的可插拔 eSIM 卡：卡上可保存多个运营商的 eSIM 配置文件，路由器使用其中处于启用状态的那一个。把卡插入卡槽后，zte-agent 可以列出配置文件、在它们之间切换、通过运营商的二维码下载新的配置文件，以及删除配置文件，全部操作都可以在 OpenU60 App 中完成。eSIM 功能就是围绕这张卡开发和测试的。

产品页面：[9esim.com/en/shop/9esim-b1](https://www.9esim.com/en/shop/9esim-b1)。B1 还带有蓝牙，供厂商的 9eSIM 手机 App 使用。OpenU60 不使用蓝牙；路由器通过调制解调器直接管理这张卡。

## 工作原理

```
OpenU60 app ──Wi‑Fi──▶ zte-agent ──QMI over QRTR──▶ modem ──▶ 9eSIM B1 (eUICC)
                            └──HTTPS (router's own data)──▶ operator's SM-DP+ (downloads, receipts)
```

zte-agent 本身就是 GSMA SGP.22 LPA，即手机用来管理 eSIM 的那类软件。它的卡片代码是开源项目 [lpac](https://github.com/estkme-group/lpac) 库的 Rust 移植。它通过调制解调器的 SIM 服务与卡上的管理应用（ISD-R）通信，路由器上无需再安装其他组件。不使用卡上的 SIM 工具箱菜单（“LPAe Menu”）；参见[限制](#限制)。

## 已测试的卡与配置

| 项目 | 值 |
|---|---|
| 卡片 | 9eSIM B1 |
| eUICC 固件 | 4.2.0 |
| SGP.22（RSP）版本 | 2.2.2 |
| 配置文件包版本 | 2.3.1（保护配置文件 1.0.0，GlobalPlatform 2.3.0，ETSI TS 102 241 9.2.0） |
| 可用存储 | 安装三个配置文件后约 950 KB；一个旅行用配置文件约占 36 KB |
| 能力 | USIM、ISIM、CSIM；Milenage 与 TUAK；附加配置文件与测试配置文件 |
| 管理应用 | 默认 ISD-R AID（`A0000005591010FFFFFFFF8900000100`），无需覆盖 |
| 受信任根 CI | 一个：GSMA RSP2 Root CI1（密钥 ID `81370f51…5bebfb`），同时用于校验和签名。运营商服务器使用由该根签发的 TLS 证书，因此 Agent 信任它（[证书说明](../zte-agent/certs/README.md)） |
| SIM 工具箱 | 提供一个菜单项“LPAe Menu”（卡片内置的配置文件切换器） |
| 路由器 | ZTE U60 Pro（MU5250），固件 `CN_ZTE_MU5250V1.0.0B27` |
| 卡片访问方式 | QMI over QRTR，QRTR 节点 3，SIM 卡槽 1（截至 2026-10-19 的测试使用 lpac 提交 `c7c8d4f`；Agent 自身的代码结果相同） |
| 配置文件 | 三个菲律宾运营商配置文件（Smart、Globe/GOMO、DITO） |

## 配置步骤

1. **先在卡上放至少一个可用的配置文件**，例如通过蓝牙使用 9eSIM 手机 App 写入。经路由器下载需要路由器自身的移动数据，而移动数据又依赖一个可用的配置文件。
2. **关闭路由器，把卡插入 SIM 卡槽，然后开机。** 路由器和普通 SIM 一样使用已启用的配置文件。固件会从内置列表中选择 APN（Smart → `smartbro`，Globe/GOMO → `homebroadband.globe.com.ph`，DITO → `internet.dito.ph`）。
3. **安装 zte-agent 并设置 Agent 密码**（见主 [README](../README.md#quick-start)）。未设置密码时，切换、下载和删除都会被拒绝。
4. **在 App 中：** 路由器 → eSIM 配置文件。

## 可用功能

| 功能 | 状态 |
|---|---|
| 列出配置文件、卡片信息 | 可用；约 0.3 s，对连接无影响 |
| 切换配置文件 | 可用；2026-10-18 在三个配置文件之间切换 20 余次，无需重启 |
| 切换校验 | 可用；Agent 依次确认卡片 → 调制解调器身份 → 数据连接（`GET /api/esim/switch`） |
| 从二维码下载（含预览与取消） | 可用；2026-10-19 从 App 安装了一个 Klook 旅行 eSIM（预览、确认，全程 31 s，占用约 36 KB 卡片存储，安装回执已送达） |
| 删除配置文件 | 可用；2026-10-19 删除了 Klook 旅行配置文件，并用其二维码重新添加（删除回执在删除后 2 s 送达）。当前启用的配置文件和未知配置文件会被拒绝。许多运营商的二维码是一次性的，因此已删除的配置文件可能无法再次下载：Klook 的可以，尽管其 FAQ 称已使用的 eSIM 无法恢复 |
| 重命名（昵称） | 可用；2026-10-19 在路由器上设置、读取并清除昵称 |
| 运营商回执 | 可用；切换测试遗留的 35 条回执于 2026-10-19 在 76 s 内送达三个运营商服务器 |

## 切换时的预期

卡片会立即完成切换，随后调制解调器重新加载 SIM。以下时间在同一测试环境测得：

| 切换后 | 现象 |
|---|---|
| 0 s | 卡片启用新配置文件，并通知调制解调器重新加载 SIM |
| ~1–8 s | 调制解调器重新加载 SIM，固件重启一次射频并选择 APN |
| 5–25 s | 无法访问卡片的管理应用（`euicc_init`，QMI 错误 80 `SimFileNotFound`）。此期间 Agent 用上一次成功读取的列表回答配置文件读取请求 |
| 6–28 s | Agent 确认卡片与调制解调器的新身份 |
| 15–45 s | 新配置文件上的移动数据连接建立；Wi‑Fi 和 App 与路由器的连接全程保持 |

如果新配置文件没有数据（余额不足、已过期、无覆盖），切换仍会完成：Agent 报告 `no_data`，但不会自行切回。可在 App 中切回；该操作无需互联网，因为全部在路由器本地完成。

## 限制

- **SIM 工具箱菜单。** 调制解调器会缓存卡上的“LPAe Menu”，但不会把 SIM 工具箱界面转发给 Agent，因此无法从 App 使用该菜单。菜单能做的事，Agent 不用它也能做，而且更多。
- **蓝牙。** 卡插在路由器中时，厂商 App 仍可通过蓝牙管理它。这与 OpenU60 无关，也未在路由器内测试。
- **功耗。** 未测量卡在 U60 卡槽中的供电电压和电流。整个测试期间（约 8 小时内切换 20 余次）工作正常；参见[检查记录](research/U60_Pro_9eSIM_B1_SSH_Findings.md)。
- **旅行 eSIM。** 旅行配置文件在另一个国家签发，因此在你的国家始终处于漫游状态：请在“路由 → 移动网络”中打开**数据漫游**，如果路由器没有自动选择，请填写提供商的 APN（2026-10-19 测试的一个 Klook 配置文件需要 `e-ideas`、PAP）。随时可以在 App 中切回本地配置文件；该操作无需互联网。启用 Klook 配置文件时，卡片在约两分钟内拒绝切出（SGP.22 `catBusy`：其 SIM 工具箱忙）。路由器最多重试 4 分钟，App 会显示正在重试。
- **其他 eSIM 卡。** 卡槽中任何 SGP.22 eUICC 都应能同样工作，包括没有 SIM 工具箱菜单的型号，因为 Agent 不使用它。目前只测试过 9eSIM B1。
